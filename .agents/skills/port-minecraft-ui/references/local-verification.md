# Maintainer local verification

GitHub Actions is disabled. Maintainers run this workflow locally before merging pull requests; contributors are not required to reproduce the maintainer workstation setup. Verify the proposed merge result and intended base. Recheck when either changes; receipts apply only to recorded source and environment. These commands do not merge or publish:

- `bun run porting:check`: types, committed evidence integrity, preview preparation and Base Pixel Perfect Tests, website tests and component behavior tests.
- `bun run check:pr`: prechecks, production builds and Base Pixel Perfect Tests, website tests and component behavior tests.

Cases in the shared suite are classified individually by `packages/tests/scripts/browser-base-cases.json`. Base entries record an actual website-default path or a pinned shadcn-owned test. Full tests are the remaining cases; choosing one Base case does not select the rest of its file or matrix. The selection is not a sample or a count/time target. Mixed edge/primary cases remain Full and gaps are reported in `docs/audits/base-selection.md` rather than filled with new tests.

`bun packages/tests/scripts/browser-suite.mjs list --base`, `list --full`, or `list --all` enumerate cases without executing them; add `--json` for inventory data. Plain `playwright test --list` also permits complete inventory collection. `bun run test -- --list` lists the ordinary Base selection. The project Playwright config and its pre-execution guard constrain normal and filtered execution to Base tests.

Full execution requires a dedicated GitHub run issue with human-maintainer-applied `full-tests:approved` authorization and a brand-new independent Codex session. A chat message or executor-applied label is not approval. Use `bun run full-tests plan`, then follow `docs/agents/full-test-runs.md` for issue creation, maintainer approval, independent dispatch and execution. The old `-Suite pixels` entrypoint remains disabled. Listing Full cases is not execution. Never substitute a direct raw Playwright command or environment flag to evade the gate.

Contributor commands are cross-platform: `bun run dev` starts the website, `bun run registry:serve` builds and serves registry JSON, `bunx --bun uncheck` runs workspace lint, formatting and type checks after `bunx turbo run generate`, and `bun run test -- <file-or-filter> --workers=1` filters within Base Pixel Perfect Tests, website tests and component behavior tests. `bun run build` builds the registry and website through Turbo. `bunx turbo run generate` prepares indexes before direct Uncheck; integrity checks remain in maintainer verification. Typechecking, production builds and tooling unit tests remain outside Base/Full classification.

Read package scripts for current suite contents. Actual shadcn CLI installation and fresh native captures remain additional gates when relevant; these commands do not perform them. Existing installation receipts apply only to their pinned sources/cases.

The Windows launcher reflects the current maintainer workstation setup: a bounded job, one browser worker, headroom guards and serialized batches. Existing local servers are outside its job: cap them separately, account for their usage and avoid duplicate instances. The workstation's limits are 80% CPU/90% RAM; these are local settings rather than contributor requirements. A resource stop leaves verification incomplete.

Ordinary logs, resource summaries and source-bound results live beneath ignored `.pixel-perfect-test/porting/`. Full receipts and claims live under the shared Git common directory, so they survive worktree cleanup and coordinate executors across worktrees. Run focused Base checks while implementing and ordinary Base verification before merge. Pending, incomplete or failed Full results are not merge blockers. Resume unfinished work only when source/environment match; never reuse a pass after its inputs change. A Base pass establishes only the selected cases, not the Full reference matrix.

Fixture, fresh CLI-consumer, and integrated-preview evidence remain distinct. Fixture pixels cannot catch surrounding CSS failures. Additional content, state, locale, viewport and interaction variants remain Full unless an existing case independently qualifies through the explicit Base rules; do not promote the complete matrix into normal verification.

Pixel Perfect Tests compare declared reference cases with zero differing decoded RGBA pixels. Temporary screenshots, diffs, metrics, fixture builds, caches and native-runtime intermediates belong beneath the repository-root `.pixel-perfect-test/`. Retained captured references and provenance stay in `packages/tests/tests/reference/`; durable Full-run receipts stay in the Git common directory. Website and component behavior tests that share the fixture also write their diagnostics beneath `.pixel-perfect-test/`.
