# Verify the Button pilot against the vanilla renderer

The pilot preserves the shadcn Button API and web interactions while matching Minecraft Java 26.2's default button appearance. Original textures and ASCII bitmap glyphs install with the component. The default is 200 × 20 logical pixels at 2× scale; scales 1–3 are configurable. Other shadcn variants remain available but are outside this pilot's fidelity guarantee. This is a private local pilot, with no release or product website.

Pixel acceptance requires zero RGBA differences against independent captures from the supplied, SHA-256-pinned vanilla JAR. A test-only Java Screen supplies labels and states while the original Button, font, and GPU renderer produce reference pixels. Browser-generated snapshots would only establish regression stability, so they cannot be the oracle. Loading overlays must be gone before capture; hashes and native provenance travel with the images. The current matrix covers normal, hover, keyboard focus, disabled, four widths, scales 1–3, and all printable ASCII in normal/disabled states. Browser verification uses Edge at device pixel ratio 1; other environments, glyph sets, dimensions, and custom children are unproven.

Original bitmap glyphs are displayed through CSS masks, with real label text retained for accessibility. Browser font rasterization changed glyph edges even with matching outlines. Native button semantics, keyboard activation, disabled behavior, props, and Radix asChild composition remain web behavior and are tested separately. A test fixture serves only automated verification; the registry server continues to serve JSON only.
