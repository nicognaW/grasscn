# Domain docs

This is a single-context repository.

Before exploring code, read root `GLOSSARY.md` and the relevant decisions in `docs/adr/`.
If either is missing, proceed silently; create domain documents only when a domain-modeling task resolves terms or decisions.

Use glossary vocabulary in issues, hypotheses, tests, and implementation discussions. Record unresolved vocabulary as a domain-modeling follow-up.
Surface any conflict with an existing ADR explicitly, naming the affected decision.
