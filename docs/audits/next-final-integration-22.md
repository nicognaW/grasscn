# Final Next/Fumadocs integration verification

Issue: [#22](https://github.com/nicognaW/grasscn/issues/22), implementing [#12](https://github.com/nicognaW/grasscn/issues/12) and ADR0004. This document describes the final acceptance contract. Source-bound runtime results live in the receipts below; this document does not turn pending or interrupted phases into passes.

## Architecture and retained boundaries

Next App Router is the sole website implementation. Fumadocs MDX owns documentation bodies, the page tree, heading/TOC extraction and text search. Narrow registry-symbol, complete installation/source and evidence adapters retain separate authoritative metadata. Superseded web Vite entry/router/home/chart/docs-generator/style modules and their web-only dependencies are retired. Reachable interactive demos and their actual support data remain additional examples. The independently built Vite fixture, original registry implementations/resources, byte-pinned captured references and separate Full gate remain intact.

The maintained `documentationInventory` is test inventory metadata from authored canonical MDX files and authoritative registry/group identities. It rejects missing or unowned pages and does not generate body/tree/TOC/search data. Independent normal and PPT inventories reconcile their exact identities. Committed main's testing architecture is authoritative: every non-PPT behavior/API/browser variant runs ordinarily, including five cases discussed historically under the older shared-suite Base policy. Only PPTs have Base/Full classification. See [the selection audit](base-selection.md) and [the committed-main reconciliation](main354-reconciliation.md). No Full PPT matrix or positive approved Full execution is part of this migration.

## Receipt locations and limitations

Final normal implementer receipts are retained under `test-results/22-final/`, ordinary consumer artifacts under `test-results/manual-consumers` and `test-results/cli-consumers`, and explicit PPT receipts under `.pixel-perfect-test/22-final/`. Workflow/development scripts report their own general artifact directories. Source commit/tree, Bun/browser/environment, production output and exact case/artifact hashes determine validity. Guard logs remain under canonical `.native-reference/nx-tools/logs/`. The root handoff identifies concrete completed receipt paths and final scope; this static contract intentionally remains valid before results are known.

Existing scoped Oxlint loading fails in eslint-plugin-github with TypeFlags.Intrinsic; this unrelated configuration debt is not a lint pass. Separately, Uncheck's Windows staged hook parsed absolute oxlint/oxfmt paths as dependency/Git specifiers and failed before those tools ran. The affected local commit used a command-scoped hook skip, without changing shared/global hook configuration. Direct guarded formatting, workspace types and the actual Oxlint configuration attempt report independently. The maintained shared resource runner already preserves unsigned process failures as a nonzero wrapper result; an outside diagnostic guard's uint exit propagation was corrected after a Bun crash, retaining the raw nonzero status in its receipt. Full positive execution/publication remains unvalidated without its separate approved run. No deployment or main merge is authorized here. Previously rejected nx16 runtime/cache cleanup is retained; this work does not retry deletion or remove that worktree to circumvent the rejection.
