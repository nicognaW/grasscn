# Final Next/Fumadocs integration verification

Issue: [#22](https://github.com/nicognaW/grasscn/issues/22), implementing [#12](https://github.com/nicognaW/grasscn/issues/12) and ADR0004. This document describes the final acceptance contract. Source-bound runtime results live in the receipts below; this document does not turn pending or interrupted phases into passes.

## Architecture and retained boundaries

Next App Router is the sole website implementation. Fumadocs MDX owns documentation bodies, the page tree, heading/TOC extraction and text search. Narrow registry-symbol, complete installation/source and evidence adapters retain separate authoritative metadata. Superseded web Vite entry/router/home/chart/docs-generator/style modules and their web-only dependencies are retired. Reachable interactive demos and their actual support data remain additional examples. The independently built Vite fixture, original registry implementations/resources, byte-pinned captured references and separate Full gate remain intact.

The maintained `documentationInventory` is test selection metadata from authored canonical MDX files and authoritative registry/group identities. It rejects missing or unowned pages and does not generate body/tree/TOC/search data. Global Playwright collection and fail-closed classification reconcile every exact identity. Five inherited mixed-variant Base mappings were corrected only after source inspection and explicit review; those exact tests remain Full. See [the selection audit](base-selection.md) for inputs, assertions, replacement default coverage and remaining gaps. No Full matrix or positive approved Full execution is part of this migration.

## Source-bound execution

Freeze source writers and commit the proposed source before final acceptance. All heavy phases use the shared named-mutex resource guard. Builds/install/types run at4% CPU with the reliable4GiB Job cap and inherited GOMEMLIMIT=768MiB, GOMAXPROCS=1 and RAYON_NUM_THREADS=1. Browser/native phases run at10%, retaining global headroom admission/pause/stop and the80%CPU/90%RAM ceilings. A resource stop is incomplete.

`verify-next-development.mjs` starts the ordinary root `bun run dev` after preserving/removing its own generated MDX/dev/env inputs to backups. It visits every canonical component document plus homepage/docs/chart routes, exercises Preview/Code and retains desktop/mobile evidence. `verify-next-workflow.mjs` executes frozen Bun install, ordered Turbo generation, direct Uncheck workspace discovery/types, root production build, actual generated-output backup/cache restoration with byte comparison, and source/config/registry invalidation probes. It restores the original source and output, retains backups and stamps a production identity only after source equality.

`verify-porting.mjs` prepare phase runs all normal tooling unit contracts, workspace types, primitive graph, registry/evidence integrity, root build and independent fixture build. Its browser phase requires unchanged preparation source/environment/build/dependency identities, owns a Bun Next production process and executes exact Base cases. Each browser receipt distinguishes website source/build/public-registry identity from fixture bundle identity. Checkpoint reuse requires matching source/environment/output and intact artifacts. The Full host adapter retains isolated ports, strict JSON404 handling and HTTP/CONNECT rejection; negative routing contracts are separate from unapproved positive Full execution.

`next-production.mjs` rejects a different source, mutated production/registry bytes and occupied ports. `acceptance-preview.mjs` requires that existing build receipt; it never stamps an arbitrary existing build as current. Serve the final reviewed integration snapshot on loopback5176 during acceptance, with source/process identity in evidence rather than product UI. Root integration/review may require a new build and receipt after this implementer snapshot.

## Consumers and visual evidence

[The external-consumer contract](next-consumer-verification-22.md) specifies actual public clipboard/download collection, separately prepared external Next/Vite applications and their visible composed/resource/WebGL runtime. The independent all-item real shadcn CLI application has its own initialization and installed dependency graph. Public payloads must match current production `/r` bytes. Consumer dependencies must physically resolve under their own modules; input/build/dependency identities must remain unchanged between ordered phases. Manual collection/runtime use real granted Clipboard API access. Website, fixture and external consumer evidence are distinct gates.

Narrow documentation Preview/Code uses the existing compact240px geometry only at narrow viewports; desktop606px remains unchanged. The actual mobile default is compared to the matching independent native Preview/Code case, with actual/diff/metrics and a one-pixel negative control. The brand SVG remains byte-pinned and renders at its intrinsic176x64 geometry; the48px grass constituent has a dedicated repeated native GUI3/#202020 context. Whole SVG/header/page composition is a web adaptation; constituent comparisons never imply a whole-page vanilla match. Desktop/mobile homepage, charts and representative docs screenshots support visual review separately.

## Receipt locations and limitations

Final implementer receipts are retained under `.pixel-perfect-test/22-final/` and the workflow/development scripts' reported directories; their source commit/tree, Bun/browser/environment, production output and exact case/artifact hashes determine validity. Guard logs remain under canonical `.native-reference/nx-tools/logs/`. The root handoff identifies the concrete completed receipt paths and final scope; this static contract intentionally remains valid before results are known.

Existing scoped Oxlint loading fails in eslint-plugin-github with TypeFlags.Intrinsic; this unrelated configuration debt is not a lint pass. Formatting, workspace types, build, native comparison and runtime gates report independently. Full positive execution/publication remains unvalidated without its separate approved run. No deployment or main merge is authorized here. Previously rejected nx16 runtime/cache cleanup is retained; this work does not retry deletion or remove that worktree to circumvent the rejection.
